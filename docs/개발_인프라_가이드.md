## 1. 전체 구조

```
        [ 개발/수정 ]
             │  git push
             ▼
      [ GitHub 저장소 ]  ← 코드의 중앙 원본 (비밀값은 없음)
        │            │
     git pull      git pull
        ▼            ▼
    [  NAS  ]      [  맥  ]
   서버 운영       앱(APK) 빌드
   (Docker)       (Android Studio/Gradle)
        │            │
        ▼            ▼
   서비스 제공     직원 폰에 설치
```

- **GitHub** = 코드 중앙 저장소. 모든 변경은 여기서 주고받는다.
- **NAS** = 서버(web/api/DB)를 Docker로 24시간 운영.
- **맥** = 안드로이드 앱(APK)을 빌드하는 개발 PC.
- 앱은 실행 시 **NAS의 공개 주소**로만 통신한다(맥과 무관).

## 5. 환경변수·비밀 관리

- **모든 비밀값은 NAS의 `/volume1/docker/Eunbi03/.env` 에만** 둔다. (`.env`는 `.gitignore`)
- Firebase 서비스 계정 키 `api/firebase-key.json` 도 **git 미포함**(gitignore). NAS에만 배치.
- 이 문서·코드·커밋·채팅에 **비밀값을 절대 남기지 않는다.**

`.env`에 들어가는 항목(값 아님, 키 목록):
```
DB_NAME, DB_USER, DB_PASSWORD
JWT_SECRET
PUBLIC_BASE_URL          # 리포트 링크 기준 주소 (예: https://공개주소/api)  ※ /admin 붙이지 말 것
SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASSWORD   # 이메일(포트 465면 secure)
SOLAPI_API_KEY, SOLAPI_API_SECRET, SMS_SENDER    # 문자(LMS)
ALLOWED_ORIGINS          # 비우면 전체 허용. 설정 시 앱 origin(https://localhost) 포함 필요
```
- Firebase 키 경로는 compose에서 `FIREBASE_KEY_PATH=/app/firebase-key.json` 으로 주입되고, `api/firebase-key.json` 이 볼륨으로 연결된다.
- ⚠️ `docker compose up` 전에 **`api/firebase-key.json` 파일이 반드시 존재**해야 한다(없으면 볼륨 마운트 오류).

## 6. 서버 배포 (NAS / Docker)

SSH로 NAS 접속 후 프로젝트 폴더에서:

```bash
cd /volume1/docker/Eunbi03
git pull
sudo docker compose build api web      # 바뀐 서비스만 빌드 (예: api web)
sudo docker compose up -d api web      # 새 이미지로 컨테이너 교체
```

확인:
```bash
sudo docker compose logs api --tail=20    # [FCM] 초기화 완료 / [스케줄러] ... 확인
sudo docker compose ps                    # 상태 running 확인
```

- 서비스 구성: `db`(Postgres) / `api`(3000) / `web`(정적 SPA) / `nginx`(80→호스트 8080). Synology 리버스 프록시가 HTTPS(공개 주소)를 nginx로 넘긴다.
- nginx는 `/api/` 만 api로 전달하고 나머지는 web(SPA)로 보낸다.
- **DB 포트는 외부에 노출하지 않는다.**

DB 접속(디버깅용):
```bash
sudo docker compose exec db psql -U <DB_USER> -d <DB_NAME>
```
(사용자·DB명은 `.env` 값. 여기 문서엔 적지 않음)

## 7. 앱 빌드 (맥 / Android)

사전 준비(최초 1회): Node 20+, Android Studio(SDK), 저장소 clone.

```bash
cd <맥의 Eunbi03 경로>
git pull
cd web
npm install                 # 최초 또는 의존성 변경 시
npm run build:mobile        # 모바일용 웹 빌드 (.env.mobile의 API 주소 주입)
npx cap sync                # 웹 빌드를 안드로이드 프로젝트에 반영 + 플러그인 동기화
cd android
export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"
./gradlew clean assembleDebug
```

- 결과 APK: `web/android/app/build/outputs/apk/debug/timecard-app-android-ver{N}.apk`
- **버전 올리기**: `web/android/app/build.gradle` 상단의 `def appVersion = N` 숫자만 올린다(낮추지 말 것).
  → versionCode / versionName(`verN`) / APK 파일명이 자동으로 맞춰진다.
- APK를 폰에 전송해 설치. 아이콘/버전 갱신이 안 보이면 **앱 완전 삭제 후 재설치 → 재부팅**.

주의:
- `export JAVA_HOME=...` 는 **한 줄로** 입력(경로에 공백 있음). 터미널에서 줄바꿈되면 실패한다.
- `xcrun` 관련 경고는 iOS 도구 문제로 안드로이드 빌드와 무관(무시). git이 안 되면 `xcode-select --install`.
- 앱 아이콘 원본은 리사이즈해 `web/android/app/src/main/res/mipmap-*/` 에 넣는다. (파일명은 소문자만 — `ic_launcher.png` 등)

|-----------|-----------|

| **안드로이드 네이티브**(위치·알림·백그라운드·아이콘) | **맥에서 APK 재빌드** → 폰 재설치 |

## 10. 푸시(FCM) 구성

백그라운드 랜덤 위치확인은 **FCM 무음(데이터) 푸시**로 동작한다.

- **서버**: `api/src/services/fcm.ts` 가 `firebase-key.json`(서비스 계정)으로 초기화. 스케줄러가 랜덤 슬롯 도래 시 해당 근로자 토큰으로 무음 푸시 발송(단기 JWT 포함).
- **앱(네이티브)**: `web/android/app/src/main/java/com/kpride/timecard/`
  - `FcmPlugin.java` — JS에서 FCM 토큰 조회
  - `TimeCardMessagingService.java` — 무음 푸시 수신 → 현재 위치 1회 측정 → `/api/random-check/native-submit` 로 전송
- **앱 설정 파일**: `web/android/app/google-services.json` (프로젝트 설정, 비밀 아님 — git 포함)
- 근로자 앱: 로그인 시 FCM 토큰을 서버에 등록(`users.fcm_token`). 위치 **"항상 허용"**, 배터리 **"제한 없음"** 필요.
- 서버 시작 로그에 `[FCM] 초기화 완료 / 푸시 사용 가능: 예` 가 떠야 정상.

### 10-1. 플랫폼별 위치 수집 (안드로이드=FCM / iOS=연속추적)

위치 수집은 하나의 Capacitor 프로젝트에서 **공통 JS + 플랫폼별 네이티브**로 구현한다. 앱을 두 벌로 나누지 않는다.

```
web/src/            공통(화면·로직). utils/push.js 에서 Capacitor.getPlatform()로 분기
web/android/…       안드로이드 네이티브: FCM 무음푸시 → 위치 → native-submit  (구현 완료)
web/ios/…           iOS 네이티브: CLLocationManager 연속추적 → 5시각 전송        (⚠️ 미구현/설계)
```

**iOS 설계 — "연속 추적 → 5회 샘플"**

iOS는 서버가 정한 시각에 백그라운드 앱을 깨울 수 없다(무음 푸시·BGTask 모두 시점 통제 불가, 위치 이벤트는 이동 시에만 발생). 따라서 근무 세션 동안 위치 매니저를 켜 **앱을 살려두고**, 내부 타이머로 **랜덤 5시각에만** 현재 위치를 `/api/random-check/native-submit`로 전송한다.

- 권장 설정: `desiredAccuracy = HundredMeters`(반경 500m 판정에 충분, 배터리↓), `distanceFilter = 100m`, `pausesLocationUpdatesAutomatically = false`, `allowsBackgroundLocationUpdates = true`, `showsBackgroundLocationIndicator = true`.
- 밑단 스트림은 이동 기준(정지 시 뜸함)이며 목적은 "좌표 수집"이 아니라 **프로세스 유지**. 실제 전송은 5회.
- 생명주기: 출근 시작 → 퇴근/기본퇴근+2h 종료 (근무 세션 한정, 종일 추적 아님).
- Info.plist:
  ```
  NSLocationWhenInUseUsageDescription
  NSLocationAlwaysAndWhenInUseUsageDescription  ("근무 시간 동안 하루 최대 5회 … 근무 외 미수집")
  UIBackgroundModes = ["location"]
  ```
- 구현 수단: `@capacitor/geolocation`만으로 부족 → 네이티브 `CLLocationManager` 커스텀 플러그인 또는 `@capacitor-community/background-geolocation`. 서버 엔드포인트·랜덤 5시각 생성 규칙은 안드로이드와 공유.
- 앱스토어 심사: 목적 명시(근태·근무시간 한정·5회), 개인정보 처리방침/라벨에 위치 표기, 백그라운드 인디케이터 노출. 무음추적형은 지양.
- 한계: 사용자가 "항상 허용"을 낮추거나 iOS가 백그라운드를 회수하면 끊길 수 있음. 포그라운드는 제약 없이 수집.
- 대안: iOS는 포그라운드 전용 수집으로 두거나, 5시각 로컬 알림 탭→수집(반자동).

**구현 상태 및 통합 절차**

- 서버(`/random-check/today-tokens`, `/native-submit`)·공통 JS(`web/src/utils/iosLocation.js`)·iOS 네이티브(`web/ios-native/BgLocationPlugin.swift`, `.m`)까지 **코드는 구현 완료**. 단, `ios/` 프로젝트는 맥에서 생성하므로 아래 통합이 필요하다. 상세는 `web/ios-native/README_iOS_통합.md`.
- 맥 요건: **Xcode 정식판**, **CocoaPods**(`brew install cocoapods` 권장 — 맥 기본 Ruby 2.6은 버전 부족).
- 절차 요약:
  1. `npm run build:mobile` → `npx cap add ios`(최초) 또는 `npx cap sync ios`
  2. `web/ios-native/`의 `BgLocationPlugin.swift`, `.m` 을 Xcode의 App/App 그룹에 추가(.m 추가 시 브리징 헤더 생성)
  3. Info.plist에 위치 사용 문구 2종 + **Background Modes → Location updates**
  4. `pod install`(cap sync가 자동 수행) → 실기기 빌드
- **iOS 앱 아이콘**: 안드로이드와 별개. Xcode `Assets.xcassets → AppIcon`에 **`web/appicon-ios-1024.png`**(1024 정사각·불투명)를 넣는다.
- 인트로/체크아웃 GIF는 웹 자산이라 iOS에도 공통 반영(별도 작업 불필요).

> **현재 상태**: 안드로이드는 구현·동작. iOS는 **코드 구현 완료, 맥 빌드·실기기 검증 단계.** 검증 전에는 아이폰은 앱을 켠 상태에서만 수집.

## 11. 트러블슈팅

| 증상 | 원인·해결 |
|------|-----------|
| `git pull`이 `local changes ... overwritten` 로 중단 | NAS/맥에 직접 둔 파일이 커밋본과 충돌. 해당 파일 백업/삭제 후 pull. |
| 재배포했는데 코드가 안 바뀜 | `git pull`이 최신인지(`git log -1`) 확인 → `docker compose build`(필요시 `--no-cache`) → `up -d --force-recreate`. |
| `[FCM]` 로그가 없음 | 옛 이미지. `git pull` 후 재빌드. `아니오`면 `api/firebase-key.json` 위치/이름 확인. |
| 앱에서 로그인 안 됨 | `npm run build:mobile`(모바일 모드)로 빌드했는지 확인. API 주소는 `.env.mobile`. |
| APK 아이콘/버전 안 바뀜 | 런처 캐시. 앱 완전 삭제 후 재설치, 재부팅. `appVersion` 올렸는지 확인. |
| 랜덤확인 미수집(모래시계 계속) | 옛 스케줄러면 api 재배포. 앱은 위치 "항상 허용" + 배터리 "제한 없음". 주말·공휴일·비정기 근무자는 애초에 생성 안 됨. |
| `JAVA_HOME invalid` | `export JAVA_HOME=...` 를 한 줄로 입력(경로 공백 주의). |
| git 명령이 `xcrun` 오류 | 맥 명령줄 도구 재설치: `xcode-select --install`. |
| 배포 후 관리자·근로자 모두 "요청 오류"/접속 불가 | **nginx 컨테이너가 안 뜬 경우**. 호스트 80은 Synology DSM 시스템 nginx가 점유하므로 compose nginx는 **8080:80**을 쓴다. `docker compose ps`로 nginx가 `8080->80`인지 확인, Synology 리버스 프록시 대상이 `localhost:8080`인지 확인. |
| 배포 후 관리자 자동로그인이 한 번 풀림 | 정상. refresh 토큰이 users→admin_devices(기기별)로 전환되는 최초 1회. 기기마다 한 번 재로그인하면 이후 유지. |
| 기기 업데이트 후 근로자 로그인 갑자기 막힘 | 예전엔 WebView UA 변화로 deviceId가 바뀌었으나, 이제 최초 1회 계산 후 localStorage 고정. 이미 어긋난 기기는 관리자 **기기 초기화** 1회. |

## 12. 보안 체크리스트

- [ ] `.env`, `firebase-key.json` 은 git에 없음(gitignore 확인). 채팅/문서/커밋에 비밀값 미포함.
- [ ] GitHub 저장소 **private**.
- [ ] Synology: 방화벽(필요 포트만), 계정 **자동 차단**, DSM **2단계 인증**.
- [ ] HTTPS 인증서(Let's Encrypt) 유지, DB 포트 미노출.
- [ ] JWT 시크릿·DB 비번은 강력하게, 노출 시 즉시 교체.
- [ ] 관리자 계정 비밀번호 정책(영문+숫자 8자 이상), 로그인 실패 잠금 동작 확인.
- [ ] 카카오 REST 키 등 과거 노출 이력이 있는 키는 **재발급** 상태 유지.
