근태관리 시스템 — 관리자 콘솔과 개발·운영 가이드

🔐 로그인 · 기기 등록

관리자 기기는 "등록"된 기기만 접속할 수 있습니다.

  • 등록된 기기 → 바로 로그인됩니다.
  • 미등록 기기 → 승인요청 화면이 뜹니다. 관리자명·전화번호·권한·권한팀을 입력해 요청하면, 권한자의 승인 후 사용할 수 있습니다.
  • 이미 쓰는 관리자명으로는 스스로 요청할 수 없습니다 → 권한자에게 기기 등록 초대 링크를 요청하세요.
  • 등록 기기를 삭제하면 그 기기는 즉시 로그아웃됩니다.

🧩 권한 체계 중복 선택

권한은 중복 선택할 수 있고, 같은 관리자명으로 등록된 기기들은 권한을 공유합니다.

근로자관리 쓰기근로자 추가·수정·삭제·비번초기화·기기변경·엑셀 업로드.

권한자위 전부 + 관리자 기기 관리 + 로그 탭. 체크와 무관하게 모든 권한.
일반 관리자는 자신의 권한 팀에 속한 근로자만 보이고 다룰 수 있습니다. 권한자·'전체' 범위는 모든 팀을 봅니다.

👥 근로자 관리

본부 > 팀으로 묶여 표시됩니다. (쓰기 권한 필요)

  • 추가 / 수정 / 삭제
  • 비번초기화 — 전화번호로 자동 초기화
  • 기기변경 — 다음 로그인 기기가 자동 등록
  • 잠금해제 — 로그인 5회 실패로 잠긴 계정
  • 엑셀 일괄 등록 — 직원 관리 시트
  • 이름 검색 / '문제계정만' 필터

📊 전체현황 · 개별 리포트

  • 전체현황 — 기간별 근태 요약 조회·엑셀 다운로드.
  • 개별 리포트 — 근로자별 월간 리포트를 이메일로 발송. 직접 선택 또는 팀/본부/법인 단위.
  • 인정 처리 — 연차·출근·퇴근·근무노트를 날짜별로 인정/해제(권한에 따라 노출).

⚙️ 설정 설정 쓰기

조직·근무 기준을 관리합니다.

  • 법인 / 본부·팀 / 직책 / 근무시간 및 직무 / 근무지 / 공휴일
  • 발송 메시지 템플릿(월간 리포트·기기 등록 초대·위치 확인 푸시)
설정 전파 — 직무의 근무/휴게시간을 수정하면, 그 직무를 쓰면서 기존 시간 그대로였던 근로자만 자동 변경됩니다(개별 조정자는 제외). 직무명 변경은 그 직무의 모든 근로자에 적용됩니다.

📝 로그 (작업 기록) 권한자 전용

설정 오른쪽의 '로그' 탭. 권한자만 볼 수 있습니다.

  • 근로자·관리자·설정·리포트·기기·인정 등 모든 변경이 일시·관리자·작업·구분·대상·비고로 기록됩니다.
  • 비고에 변경 전후값이 남습니다. 예: (이름)홍길동->김철수, (출퇴근)09:00~18:00->09:00~16:00, 연차 인정(10/22)
  • 기간·관리자명·근로자명으로 검색. 1년 보관 후 자동 삭제.

🛡️ 권한자 2명 유지 규칙

권한자가 1명으로 떨어지면 복구가 번거로워지므로, 항상 최소 2명(2그룹)을 유지합니다.

  • 권한자 그룹의 마지막 기기는, 권한자가 2명뿐이면 삭제할 수 없습니다.
  • 권한자 변경(이전)은 대상 관리자 이름의 모든 기기에 적용됩니다. 결과가 2명 미만이 되면 거부됩니다.
  • 권한자 계정의 이름을 기존의 다른 관리자 이름으로 바꾸는 것(병합)은 거부됩니다. 반대로 일반 관리자를 권한자 이름으로 바꾸면 그 관리자가 권한자가 됩니다.
권한자를 넘기려면 '권한자 변경' 버튼을 사용하세요. 이름 변경으로 권한을 옮기지 않습니다.

🚀 배포

NAS 리포지터리에서:

# 최신 코드 받기
git pull origin <branch>

# api·web 둘 다 재빌드 (한쪽만 하면 반영 안 됨)
sudo docker compose build api web
sudo docker compose up -d
용어·UI 변경이 안 보이면 십중팔구 web 미빌드이거나 브랜치 미반영입니다. git log --oneline -3로 커밋 확인 후 api·web 모두 빌드하세요.

🧩 권한 모델

  • 권한은 기기(admin_devices)에 붙고, 같은 device_name(관리자명) 그룹끼리 공유됩니다.
  • admin_devices.permissions TEXT[] — 키: staff, report_leave, report_full, settings (빈 배열=읽기전용)
  • admin_devices.is_authority — 권한자. 키와 무관하게 전부 허용. 항상 2그룹 이상 유지.
  • 유효 키·정규화는 api/src/utils/permissions.ts (VALID_PERMS, normalizePerms)로 일원화.
  • 서버 가드: hasPerm / requirePerm / needPerm, 팀 범위: getReadScope / assertWorkerInScope, 권한자: reqIsAuthority.

🗄️ 주요 데이터 & 잡

테이블

  • users — 근로자/관리자(공용 계정), device_id 단일 기기
  • admin_devices — 관리자 기기·권한·권한자
  • attendance_records — 출퇴근·연차
  • audit_logs — 작업 기록(1년)
  • random_location_checks — 랜덤 위치 확인

마이그레이션 · 잡

  • api/migrations/*.sql — api 기동 시 자동 실행
  • 랜덤 체크 슬롯 — 근무일마다 근로자별 3개 생성(스케줄러)
  • 감사 로그 1년 경과 시 자동 삭제

✉️ 알림 (이메일 / SMS)

  • 이메일 SMTP 비밀번호 환경변수: SMTP_PASSWORD (SMTP_PASS 아님)
  • 보안 연결: 포트 465일 때 secure: true
  • 발신 메시지 내용은 message_templates DB 행 — 코드의 기본값은 최초 시드용. 기존 행은 콘솔(설정 → 발송 메시지)에서 수정.

⚠️ 주의 사항

  • 엑셀 업로드 시트명 직원 관리는 데이터 매칭용 → 변경 금지(관리자 콘솔 용어는 '근로자').
  • 근로자 로그인은 한 기기가 여러 계정에 바인딩될 수 있습니다(현재 의도된 허용 상태).
  • 권한자 이전/삭제/이름변경은 전부 2그룹 유지 규칙으로 막혀 있습니다.

💻 자주 쓰는 명령

컨테이너 환경변수로 DB 접속(사용자명·DB명 하드코딩 금지).

# DB 접속(psql)
sudo docker compose exec -T db sh -c \
  'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"' <<'SQL'
SELECT device_name, is_authority FROM admin_devices
WHERE is_authority = TRUE ORDER BY device_name;
SQL
# 권한자 비상 복구(특정 관리자명을 권한자로)
UPDATE admin_devices SET is_authority = TRUE
WHERE device_name = '관리자명' AND is_approved = TRUE;
