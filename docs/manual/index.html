근태관리 시스템 — 관리자 콘솔과 개발·운영 가이드

🔐 로그인 · 기기 등록

관리자 기기는 "등록"된 기기만 접속할 수 있습니다.

  • 등록된 기기 → 바로 로그인됩니다.
  • 미등록 기기 → 승인요청 화면이 뜹니다. 관리자명·전화번호·권한·권한팀을 입력해 요청하면, 권한자의 승인 후 사용할 수 있습니다.
  • 이미 쓰는 관리자명으로는 스스로 요청할 수 없습니다 → 권한자에게 기기 등록 초대 링크를 요청하세요.
  • 등록 기기를 삭제하면 그 기기는 즉시 로그아웃됩니다.

🧭 최초 세팅 순서

근로자는 소속·근무 기준이 먼저 있어야 등록되므로, 설정부터 채운 뒤 사람을 넣습니다.

  1. 법인 등록 — 설정 → 법인
  2. 본부 · 팀 등록 — 설정 → 본부·팀 (팀 추가 시 담당 관리자 권한팀도 지정)
  3. 직책 등록 — 사원/선임 등
  4. 근무시간 및 직무 등록 — 직무명 + 근무/휴게시간
  5. 근무지 등록 — 주소·반경(출퇴근 위치 기준)
  6. 공휴일 등록 — 근무일 판정·랜덤체크 제외
  7. 근로자 등록 — 위 항목들을 선택해 배정
순서가 꼬이면 근로자 등록 화면에서 선택할 법인/팀/직무/근무지가 안 보입니다. 설정을 먼저 채우세요.

🧩 권한 체계 중복 선택

권한은 중복 선택할 수 있고, 같은 관리자명으로 등록된 기기들은 권한을 공유합니다.

👥 근로자 관리

본부 > 팀으로 묶여 표시됩니다. (쓰기 권한 필요)

  • 추가 / 수정 / 삭제
  • 비번초기화 — 전화번호로 자동 초기화
  • 기기변경 — 다음 로그인 기기가 자동 등록
  • 잠금해제 — 로그인 5회 실패로 잠긴 계정
  • 엑셀 일괄 등록 — 직원 관리 시트
  • 이름 검색 / '문제계정만' 필터

📊 전체현황 · 개별 리포트

  • 전체현황 — 기간별 근태 요약 조회·엑셀 다운로드.
  • 개별 리포트 — 근로자별 월간 리포트를 이메일로 발송. 직접 선택 또는 팀/본부/법인 단위.
  • 인정 처리 — 연차·출근·퇴근·근무노트를 날짜별로 인정/해제(권한에 따라 노출).

⚙️ 설정 설정 쓰기

조직·근무 기준을 관리합니다.

  • 법인 / 본부·팀 / 직책 / 근무시간 및 직무 / 근무지 / 공휴일
  • 발송 메시지 템플릿(월간 리포트·기기 등록 초대·위치 확인 푸시)
설정 전파 — 직무의 근무/휴게시간을 수정하면, 그 직무를 쓰면서 기존 시간 그대로였던 근로자만 자동 변경됩니다(개별 조정자는 제외). 직무명 변경은 그 직무의 모든 근로자에 적용됩니다.

근무지 — 거래처 > 지점

  • 지점이 여러 개면 거래처로 묶여 보입니다(거래처명 + 참고반경, 아래 N개 점). 거래처를 누르면 지점(지점명·주소)이 펼쳐집니다.
  • 참고반경은 거래처 공통 — 거래처 '수정'에서 거래처명·참고반경을 바꾸면 모든 지점에 적용됩니다.
  • 지점명 클릭 → 지점명·주소 수정. 지점 리스트의 삭제 → 체크 후 '확인'으로 여러 지점 한 번에 삭제.
  • 지점이 1개뿐이면 지금처럼 평면 형태로 보이고, 수정 시 주소·상세주소까지 바로 편집합니다.
  • 각 거래처 행의 수정 왼쪽 '추가' 버튼 → 지점명·주소·상세주소만 입력해 그 거래처에 지점을 바로 추가(반경은 거래처 공통, 좌표 자동).
  • + 근무지 추가에서 이미 있는 거래처명을 입력하면 "동일한 거래처가 존재합니다. 지점으로 추가하시겠습니까?" 팝업이 떠서, 확인하면 지점으로 추가됩니다(지점명 필수).
  • 삭제는 비활성 처리라 과거 출퇴근 기록은 그대로 보존됩니다(목록에서만 사라짐).

엑셀 양식 — 시트명 근무지 추가, 2행 헤더·3행부터 데이터:

A 거래처명B 지점명(빈칸 가능)C 참고반경(m)D 주소E 상세주소
이마트강릉점500강원 강릉시 경강로 2100(선택)

📝 로그 (작업 기록) 권한자 전용

설정 오른쪽의 '로그' 탭. 권한자만 볼 수 있습니다.

  • 근로자·관리자·설정·리포트·기기·인정 등 모든 변경이 일시·관리자·작업·구분·대상·비고로 기록됩니다.
  • 비고에 변경 전후값이 남습니다. 예: (이름)홍길동->김철수, (출퇴근)09:00~18:00->09:00~16:00, 연차 인정(10/22)
  • 기간·관리자명·근로자명으로 검색. 1년 보관 후 자동 삭제.

🛡️ 권한자 2명 유지 규칙

권한자가 1명으로 떨어지면 복구가 번거로워지므로, 항상 최소 3명(3그룹)을 유지합니다.

  • 권한자 그룹의 마지막 기기는, 권한자가 2명뿐이면 삭제할 수 없습니다.
  • 권한자 변경(이전)은 대상 관리자 이름의 모든 기기에 적용됩니다. 결과가 2명 미만이 되면 거부됩니다.
  • 권한자 계정의 이름을 기존의 다른 관리자 이름으로 바꾸는 것(병합)은 거부됩니다. 반대로 일반 관리자를 권한자 이름으로 바꾸면 그 관리자가 권한자가 됩니다.
권한자를 넘기려면 '권한자 변경' 버튼을 사용하세요. 이름 변경으로 권한을 옮기지 않습니다.

✅ 자주 하는 작업 (단계별)

근로자관리/개별리포트/설정 등 해당 권한이 있어야 버튼이 보입니다.

근로자 1명 추가
  1. 근로자 관리 → + 근로자 추가
  2. 이름·전화번호(필수), 소속(법인/본부/팀)·직책·직무·근무지 선택
  3. 저장 → 초기 비밀번호 = 전화번호로 생성됩니다
  4. 근로자가 그 번호로 로그인 → 최초 1회 비밀번호 변경
엑셀로 여러 명 한 번에 등록

시트 이름은 반드시 직원 관리. 2행이 헤더, 3행부터 데이터. 열 순서:

이름직책전화번호이메일근무지비고법인본부팀직무근무노트 제외비정기적
홍길동사원010-1234-5678(선택)새말센터(선택)케이프라이드MS본부MS팀영업관리1 또는 공란1 또는 공란
  • 근무지·직무·법인/본부/팀은 설정에 미리 등록된 이름과 정확히 일치해야 합니다(없으면 실패 행으로 표시).
  • 근무노트 제외·비정기적: 해당이면 1, 아니면 비움.
  • 전화번호가 중복이면 기존 계정으로 매칭(삭제된 계정은 자동 복구).
  1. 근로자 관리 → 엑셀 업로드 → 파일 선택
  2. 결과 화면에서 성공/실패 확인(실패 행은 사유 표시)
관리자(동료) 기기 등록 초대하기 권한자
  1. 근로자 관리에서 관리자 카드 → + 관리자 추가(또는 기기코드 옆 ＋)
  2. 관리자명·이메일·전화·권한·권한팀 입력 → 초대 링크 발송(이메일·문자)
  3. 상대가 등록할 기기에서 링크를 열면 등록 완료 → 바로 로그인
같은 관리자명으로 추가하면 그 그룹의 권한을 그대로 상속합니다.
비밀번호 초기화 / 기기변경
  • 비번초기화 — 근로자 행의 '비번초기화' → 비밀번호가 전화번호로 초기화. 근로자에게 전화번호로 로그인하라고 안내.
  • 기기변경 — '기기변경' 클릭 후, 근로자가 새 기기에서 다음 로그인 하면 그 기기가 자동 등록됩니다(별도 승인 없음).
  • 잠금해제 — 로그인 5회 실패로 잠긴 계정은 '잠금해제'.
월간 리포트 발송 / 연차·출근 인정 개별리포트
  • 리포트 발송 — 개별 리포트에서 대상(직접 선택 또는 팀/본부/법인) 지정 → 발송. 근로자 이메일이 등록돼 있어야 전송됩니다.
  • 인정 처리 — 날짜 셀에서 연차·출근·퇴근·근무노트를 인정/해제. (연차=개별리포트(연차), 출퇴근·노트=개별리포트(전체) 권한 필요)
🖼️ 스크린샷 자리 — 실제 화면 캡처를 주시면 각 단계에 넣어 드립니다.

🆘 문제 해결 FAQ

근로자가 로그인이 안 돼요
  • 비밀번호를 모름 → 비번초기화(전화번호로 초기화) 후 전달.
  • "등록되지 않은 기기" → 기기가 바뀐 것. 기기변경 누른 뒤 그 기기에서 로그인.
  • "계정 잠김" → 5회 실패. 잠금해제.
근로자가 폰을 바꿨어요
근로자 행 → 기기변경 → 근로자가 새 폰에서 로그인하면 자동으로 새 기기가 등록됩니다. (기존 폰은 자동 해제)
월간 리포트 이메일이 안 가요
  • 해당 근로자에게 이메일이 등록돼 있는지 확인(없으면 발송 대상에서 빠짐).
  • 설정 → 발송 메시지의 월간 리포트 템플릿 내용 확인.
  • 발송 결과 화면의 실패 사유 확인.
새 관리자 기기를 승인하려면 권한자
권한자 계정에서 근로자 관리 → 관리자 기기 영역의 승인 대기 기기를 승인. 또는 애초에 초대 링크로 등록하면 승인 단계가 없습니다.
버튼(추가/수정/발송/설정)이 안 보여요
  • 해당 권한이 없는 것입니다(읽기 전용은 버튼이 숨겨집니다). 권한자에게 권한 추가를 요청하세요.
  • 방금 권한을 받았다면 새로고침/재로그인 후 반영됩니다.
  • '로그' 탭·기기 관리는 권한자 전용입니다.
권한자가 1명만 남을까 걱정돼요
시스템이 항상 최소 3명을 강제합니다. 마지막 권한자 기기 삭제·이전·이름변경은 자동으로 막히니, 먼저 다른 관리자에게 권한자 변경으로 넘기세요.

🧩 권한 모델

  • 권한은 기기(admin_devices)에 붙고, 같은 device_name(관리자명) 그룹끼리 공유됩니다.
  • admin_devices.permissions TEXT[] — 키: staff, report_leave, report_full, settings (빈 배열=읽기전용)
  • admin_devices.is_authority — 권한자. 키와 무관하게 전부 허용. 항상 2그룹 이상 유지.
  • 유효 키·정규화는 api/src/utils/permissions.ts (VALID_PERMS, normalizePerms)로 일원화.
  • 서버 가드: hasPerm / requirePerm / needPerm, 팀 범위: getReadScope / assertWorkerInScope, 권한자: reqIsAuthority.

  • 랜덤 체크 슬롯 — 근무일마다 근로자별 3개 생성(스케줄러)
  • 감사 로그 1년 경과 시 자동 삭제

✉️ 알림 (이메일 / SMS)

  • 이메일 SMTP 비밀번호 환경변수: SMTP_PASSWORD (SMTP_PASS 아님)
  • 보안 연결: 포트 465일 때 secure: true
  • 발신 메시지 내용은 message_templates DB 행 — 코드의 기본값은 최초 시드용. 기존 행은 콘솔(설정 → 발송 메시지)에서 수정.

⚠️ 주의 사항

  • 엑셀 업로드 시트명 직원 관리는 데이터 매칭용 → 변경 금지(관리자 콘솔 용어는 '근로자').
  • 근로자 로그인은 한 기기가 여러 계정에 바인딩될 수 있습니다(현재 의도된 허용 상태).
  • 권한자 이전/삭제/이름변경은 전부 2그룹 유지 규칙으로 막혀 있습니다.

💻 자주 쓰는 명령

컨테이너 환경변수로 DB 접속(사용자명·DB명 하드코딩 금지).

# DB 접속(psql)
sudo docker compose exec -T db sh -c \
  'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"' <<'SQL'
SELECT device_name, is_authority FROM admin_devices
WHERE is_authority = TRUE ORDER BY device_name;
SQL
# 권한자 비상 복구(특정 관리자명을 권한자로)
UPDATE admin_devices SET is_authority = TRUE
WHERE device_name = '관리자명' AND is_approved = TRUE;
